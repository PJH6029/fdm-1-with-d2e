# IDM

Canonical source: `../CANONICAL_SPEC.md`.
Survey source: `../../literature_survey/MASKED_DIFFUSION.md`.

## Role

Train an inverse dynamics model on labeled D2E recordings and use it to pseudo-label video-only/unlabeled gameplay. The main reproduction target is a non-causal **masked discrete diffusion** IDM: video is fixed conditioning, and target action slots are generated by iterative denoising.

Future visual context is allowed for IDM because inverse dynamics infers the action that caused an observed screen transition. This does not make IDM a deployable causal policy; it makes it a labeler for training FDMs.

## Input/output

```text
conditioning:
  video tokens around target 50ms bins
  optional past action/state context before t

generated target:
  serialized action tokens for the target 50ms bin or short target window
```

Default observation window:

- target bin `[t, t+50ms)`;
- bounded past visual/action context before `t` with length `C_past`;
- future visual context after `t`, parameterized by offset `τ` and width `C_future`;
- default future offset `τ = 100ms`.

`τ` is the future visual evidence offset/anchor, not the entire video context length. `C_future` is how much visual time is read around or after that anchor. Each run must record the actual past/future frame span, token count, temporal resampler settings, and future-window policy.

Future visual policy should be ablated rather than assumed:

- **anchor-start:** `[t+τ, t+τ+C_future)`; simplest interpretation of offset + width.
- **anchor-centered:** `[t+τ-C_future/2, t+τ+C_future/2)`; tests whether transition evidence around the anchor matters.
- **post-target:** `[t+50ms, t+50ms+C_future)`; tests cumulative evidence immediately after the target action bin.

Initial sweep: `τ=0ms` vs `100ms`, `C_future=50ms` vs `150ms`, using anchor-start and post-target first. Add anchor-centered only if the first sweep is ambiguous.

## Candidate and reference set

### D2E-Generalist-IDM-1B — public reference objective

Use the public D2E Generalist-IDM-1B checkpoint/inference path as the primary IDM reference objective. Evaluate it on the same local split manifests, 50ms timebase, prediction-to-MCAP conversion, and D2E-style metrics used for our IDM. Record checkpoint revision and any known overlap between its training data and our evaluation recordings.

This is the target reference for IDM quality. The reproduction should match or exceed it; if not, the final report must quantify the gap and explain likely causes. If overlap cannot be ruled out, report it as a public target rather than a clean held-out baseline.

### IDM-MDLM-16 — main FDM-1-style candidate

Main candidate. This is the default recipe unless a later decision explicitly promotes another objective.

```text
video/context tokens
+ partially masked target action tokens
+ temporal/modality/slot embeddings
+ diffusion timestep/noise embedding
→ bidirectional denoising transformer or action denoiser with cross-attention to video
→ action-family heads for target slots
```

Required properties:

- diffuse only target action slots; keep video/context tokens visible;
- use absorbing `MASK_ACTION` corruption first;
- condition the network on sampled timestep/noise level;
- train with weighted masked-token CE under a diffusion schedule;
- infer from fully masked target action slots with a 16-step confidence-guided sampler;
- enforce valid vocab/state constraints per action slot where possible.

Implementation can start with a bidirectional interleaved transformer. If long video context is too expensive, use a compact action denoiser that cross-attends to cached video features.

### IDM-MD4/SGMD — continuous-time/state-dependent diffusion candidate

Use MD4/SGMD-style continuous-time masking and weighted CE when the simple MDLM-style schedule underperforms or calibration is poor. This is the preferred second serious candidate because state/action-dependent schedules map naturally to D2E action imbalance.

### IDM-ActionSchedule — action-family schedule ablation

Action-family/state-dependent masking, sampling, or loss weighting:

- no-op tokens: prevent no-op collapse without inflating false positives;
- mouse movement: preserve dense movement quality and scale;
- keyboard/buttons/scroll: improve sparse event recall while tracking precision;
- invalid transitions: avoid impossible key/button states.

This should be tested as an ablation on top of IDM-MDLM-16 or IDM-MD4/SGMD, not as a separate architecture family.

### IDM-Corrective/Remask — correction robustness candidate

If confidence-guided decoding produces high-confidence false positives, stuck keys, or impossible visible states, add correction-oriented training or sampler remasking. This candidate trains/evaluates the ability to revise visible wrong tokens, not only fill masked tokens.

### IDM-Partial/Soft — advanced refinement candidate

Use partial-mask embeddings or soft embedding interpolation only if binary mask/unmask decoding wastes steps or creates unstable action jumps. This is advanced and should wait until IDM-MDLM-16 and IDM-MD4/SGMD are measured.

### IDM-VLA-style chunk decoder — future action-structure candidate

Borrow discrete-diffusion VLA ideas only after the core FDM-1-style IDM is working: localized action vocabularies, structured/chunk decoding, adaptive reveal order, and secondary remasking for action chunks. This is a later candidate, not the first implementation target.

### Sanity/floor objectives

These are useful but must not be treated as the reproduction target:

- **IDM-CE:** one-shot non-causal classifier over target action slots. Use as data/evaluator sanity check, performance floor, and possible initialization for diffusion training.
- **IDM-MLM:** random-mask denoising without a principled timestep/noise schedule. Use to isolate the value of true diffusion scheduling and iterative sampling.
- **IDM-Sanity Priors:** no-op/zero-mouse and action-frequency priors. Use only as evaluator sanity checks.

### Other diagnostic variants

- **IDM-Calibrated:** temperature scaling, entropy/confidence thresholds, and per-token-family filtering applied to the promoted IDM for pseudo-labeling.
- **IDM-Causal Ablation:** past-video-only ablation used to quantify the value of future context. This is an architectural ablation, not the primary external baseline.
- **IDM-Specialist:** per-game specialist only as an upper-bound diagnostic if compute allows; not the headline reproduction target.

## Training objective

Let `x0 = (x0_1, ..., x0_L)` be the clean serialized action-token sequence for the target bin/window. Let `c` be the visible conditioning context: video tokens, optional past action tokens, temporal metadata, and valid-action masks.

Default FDM-1-style masked diffusion objective:

```text
sample noise level u ~ p(u)
sample binary mask m_i ~ Bernoulli(p_mask(u)) over target action slots
x_u_i = MASK_ACTION if m_i = 1 else x0_i
predict p_theta(x0_i | x_u, c, u) for target slots
L_IDM = E_u,m [ sum_i m_i * w(u) * alpha_family(i) * CE(x0_i, p_theta_i) ]
```

Notes:

- CE is the practical token loss, but the objective is diffusion only when it includes the corruption process, noise/timestep conditioning, schedule weighting, and reverse sampler.
- Use slot-local vocabularies or invalid-token masks when available; a keyboard slot should not compete with irrelevant mouse tokens.
- Optional auxiliary heads such as next-click/state prediction may be added only if they improve calibrated action metrics or diagnose failures.
- Balanced sampling/loss weighting is allowed, but unweighted primary D2E metrics and sparse-event precision/recall must still be reported.

## Inference and pseudo-labeling

Default sampler is 16 steps, matching the public FDM-1 IDM clue.

```text
1. initialize all target action slots as MASK_ACTION
2. for each scheduled reverse step s = 1..16:
     predict clean-token distributions for masked/uncertain slots
     compute confidence per slot/token family
     reveal the scheduled highest-confidence predictions
     optionally remask constraint-violating or low-confidence visible tokens
3. return final action tokens plus confidence/calibration statistics
```

Required sampler sweep:

| Steps | Purpose |
| --- | --- |
| 1 | one-shot masked classifier equivalence / throughput floor |
| 4 | cheap pseudo-labeling candidate |
| 8 | midpoint and comparison to older local draft |
| 16 | default FDM-1-aligned setting |
| 32 | quality/calibration ceiling if compute allows |

Pseudo-label filtering uses the calibrated promoted IDM, not raw logits alone. Track coverage/quality tradeoffs by token family and game.

## Required ablations

Minimum:

- D2E-Generalist-IDM-1B public reference on the same split/evaluator path;
- IDM-CE and IDM-MLM as sanity/floor objective ablations;
- IDM-MDLM-16 as the main objective;
- causal vs non-causal context;
- `τ=0ms` vs `τ=100ms`;
- future visual policy/width: anchor-start vs post-target, `C_future=50ms` vs `150ms`;
- sampler steps `1/4/8/16` and `32` if compute allows;
- confidence filtering on/off for pseudo labels.

Add when diagnostics justify:

- context `2s` vs `10s`;
- anchor-centered future visual policy;
- MD4/SGMD continuous-time or state-dependent schedule;
- action-family/state-dependent schedules;
- corrective/remasking training;
- partial/soft refinement;
- compound mouse token vs separate X/Y if sparsity or NLL indicates tokenization problems;
- per-game specialist upper-bound.

## Evaluation

Headline metrics are the D2E 50ms-bin metrics:

- mouse Pearson X/Y;
- mouse scale ratio X/Y;
- mouse-button accuracy;
- keyboard key accuracy.

Report:

- micro-average;
- per-game macro-average;
- held-out-game macro-average;
- calibration/confidence vs correctness for pseudo-labeling;
- pseudo-label distribution and no-op/event rates;
- impossible key/button state rate.

Diffusion-specific diagnostics should be logged but not replace headline claims:

- masked-action NLL by noise level/timestep;
- per-action-family NLL, accuracy, precision/recall/F1;
- calibration/ECE by diffusion step and final token;
- sampler step quality/throughput curve;
- high-confidence false-positive analysis;
- pseudo-label usefulness: train the same small FDM on GT vs pseudo labels.

## Success criteria

- D2E-Generalist-IDM-1B is evaluated on the same splits/evaluator path.
- IDM-MDLM-16 or a promoted diffusion variant matches or exceeds D2E-Generalist-IDM-1B on primary metrics, or the gap is reported as a reproduction limitation.
- Direct CE, MLM, priors, and causal variants are reported only as floors/diagnostics, not as success baselines.
- Calibration predicts correctness well enough to filter labels.
- Pseudo-labels do not collapse to no-op, stuck keys, or impossible button/key states.
- Sparse keyboard/button metrics are reported separately from mouse metrics.
- 16-step inference is the default reported diffusion setting; lower-step settings are speed ablations.
